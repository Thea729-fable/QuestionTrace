# 题迹 QuestionTrace

> 从真实面经追溯每一道题。

用户把岗位 JD 和简历交给普通联网 Agent 后，常见结果是：搜索少量网页或汇总帖，读取标题、摘要和部分正文，再结合模型已有知识直接生成问题。这种方式虽然快，但搜索覆盖范围不透明，容易混入二手搬运和过时内容，也常常遗漏藏在小红书长图里的真实题目；同一面经是否重复、每道题来自哪里、为什么适合当前候选人，通常无法核验。

QuestionTrace 是一个适用于任何岗位、由 **Museon 实时社媒监测与研究能力驱动**的求职押题 Agent Skill。它会先根据用户上传的 JD 动态确定具体职位和受控检索词，再由 Museon 对小红书等社媒执行原生检索、打开原始帖子、深读正文并逐张分析题图，同时通过公开网页研究补充牛客面经。完成去重、聚类和时效加权后，形成该岗位本轮专属的**真实面经证据库（面经题库）**，最后才结合用户简历生成押题结果。每道高优先级题都必须同时具有“真实面经证据 × JD 要求 × 简历触发点”，因此题目覆盖更全面、岗位与候选人匹配更准确，结论也可以追溯核验。

Museon 在 QuestionTrace 中不是一个普通搜索入口，而是实时社媒面经监测层：它让 Agent 能够接触社媒原帖、帖子正文、题图和发布时间等社媒原生信息，而不是只看到通用搜索引擎返回的网页摘要。这里的“监测”指每次任务围绕当前 JD 发起的实时检索、深读和视觉分析，不是未经用户授权在后台持续抓取。

它不限定 AI 产品经理。只要存在可公开检索的岗位面经，产品、运营、算法、研发、设计、销售、职能等岗位都可使用。AI 产品经理 JD 会检索 AI 产品经理面经，商业化产品经理 JD 会检索商业化、广告和变现产品经理面经；其他岗位也会生成自己的岗位词、相近岗位词、公司词和技能词，而不是套用固定题库。

## 与普通联网 Agent 的差异

| 维度 | 普通联网 Agent 的常见做法 | QuestionTrace |
| --- | --- | --- |
| 数据源真实性 | 可能混合搜索摘要、SEO 汇总、二手转载和模型记忆 | 通过 Museon 原生检索小红书社媒原帖，并读取牛客原文；保留原始链接、公司、岗位、日期和轮次，广告、搬运及无法核验内容不进入核心证据 |
| 检索全面性 | 搜索少量关键词和靠前结果，覆盖过程通常不可见 | 从 JD 生成“公司＋精确岗位＋相近岗位＋业务方向＋核心技能”检索梯度，以小红书、牛客为主并按需补充其他公开来源；持续翻页到新增有效样本趋于饱和 |
| 内容完整性 | 容易停留在标题、摘要或正文片段 | 标题和摘要只算候选线索；纳入题库前必须读完可获得正文，并逐张检查全部相关题图，未读完即排除或降级 |
| 信息时效性 | 可能混用多年以前的通用题库，时间权重不明确 | Museon 每次根据当前 JD 发起实时社媒检索；默认覆盖近三年，并提高最近六个月样本权重，明确记录采集日期和证据日期 |
| 信息丰富度 | 主要输出问题列表 | 同时提取原始问题、面试轮次、公司与岗位背景、面试官考察意图、候选人品质、连续追问及题图证据 |
| 个性化程度 | JD、简历和网络结果往往只是并列总结 | 强制进行“面经证据 × JD 要求 × 简历触发点”三方匹配；没有三方证据的问题不能进入最高优先级 |
| 可核验性 | 很难知道是否读过原文、看过图片或去过重 | 记录正文完整性、图片总数/已读数/不可读数、重复关系和来源链接，并通过审计脚本检查 |

## 核心价值

- **Museon 社媒监测驱动**：使用 Museon 的社媒原生检索、帖子深读和视觉分析能力获取小红书等平台的一手面经，并通过公开网页研究覆盖牛客。
- **真实性**：优先采用原始面经而非搜索摘要或二手题库；每条核心证据都保留来源和读取状态。
- **全面性**：组合公司、精确岗位、相近岗位、业务方向和技能词进行分层检索，并持续扩展到证据趋于饱和。
- **时效性**：围绕当前 JD 实时检索，默认覆盖近三年，并重点提高最近六个月面经权重。
- **丰富度**：不仅提取问题，还读取正文和题图中的轮次、业务背景、考察意图、候选人品质及连续追问。
- **真实证据库驱动**：先构建本次岗位的可追溯面经题库，再生成押题；不依赖模型记忆临时拼题。
- **任何岗位适用**：检索对象由当前 JD 动态决定，不写死 AI 产品经理或某一行业。
- **实时**：使用用户自己的 Museon 授权获取当前岗位相关面经，不依赖内置的过期全网数据库。
- **深读**：标题和摘要只作候选线索；只有读完正文并核对全部相关题图的面经才能计入证据。
- **个性化**：每道高优先级题必须同时对应真实面经、目标 JD 和候选人简历。
- **可追溯**：保留原始链接、日期、公司、岗位、轮次、正文及图片读取状态。
- **可审计**：自动检查正文完整性、图片覆盖率、去重状态和高优先级题的三方证据。

## 安装

仓库发布后，可使用 Agent Skills 安装器：

```bash
npx skills add Thea729-fable/QuestionTrace
```

也可以从本地仓库安装：

```bash
npx skills add ./skills/question-trace
```

在支持 Skills 的 Agent 中调用：

```text
使用 $question-trace，根据我上传的岗位 JD 和简历调研近期真实面经，生成可追溯的押题题库 Markdown。
```

## 运行依赖

核心运行时只要求：

1. 支持 Agent Skills 的宿主 Agent；
2. Museon CLI v0.5.9 或兼容版本；
3. 用户本人完成 Museon 浏览器授权。

QuestionTrace 不接收、保存或转发用户的 Museon Key。授权缺失时，Agent 发起 Museon 官方设备授权，成功后自动恢复原任务。

百炼 CLI 是开发和可选复核能力，不是普通用户的第二个必需授权。本项目开发中使用了：

- `qwen3.5-omni-plus`：读取演示 JD 图片并生成岗位检索词；
- `qwen3.8-max`：审查 Skill 架构、深读准入门槛和自动审计规则；
- 百炼 WebSearch MCP：曾尝试用于牛客补充检索，但当前账号未开通，因此未作为必需路径。

## 工作流程

```text
JD + 简历
  → 动态岗位识别与受控检索词
  → Museon 实时社媒监测：小红书原生搜索 + 牛客公开网页发现
  → 候选筛选
  → 逐份完整阅读正文 + 逐张检查题图
  → 证据台账、去重与自动审计
  → 面经 × JD × 简历三方匹配
  → 15 分准备优先级
  → 个性化押题题库 Markdown
```

## 证据规则

凡被纳入样本、计入频次或用于押题的面经，必须：

- 打开原始页面，而不是停留在搜索结果；
- 完整读取可获得的正文；
- 统计全部题图并逐张记录读取状态；
- 对不可读图片说明原因，不伪造内容；
- 标记公司、岗位、日期和面试轮次；
- 与转载、镜像和重复帖子去重；
- 通过 `audit_evidence.py` 的证据完整性检查。

未打开的标题或摘要只能留在候选池，不得进入频次统计。

## 准备优先级

每个问题主题按 15 分制计算：面经频次 4 分、时效 3 分、JD 相关性 3 分、简历触发强度 3 分、公司与岗位相似度 2 分。

- 12–15：高优先级
- 8–11：中优先级
- 0–7：低优先级

该分数是相对准备优先级，不是命中概率或结果保证。

## 演示案例

仓库只提供一个端到端脱敏案例：虚构候选人“林思远”应聘**阿里巴巴 AI Agent 产品经理（2027 届应届生）**，岗位 JD 见 `demo/inputs/` 中的两张截图。

演示使用已完成深度审计的真实 AI 与 Agent 产品经理历史证据回放：

- 42 份公开面经；
- 19 家公司；
- 147 张去重高分辨率题图；
- 题图中直接识别 640 条原始问题项；
- 最终生成一份约 50 分钟面试路线的个性化准备题库。

为方便评委无需重新授权即可查看完整效果，这一个案例采用截至 2026-08-07 的证据回放；实际用户运行时仍会根据当前上传的 JD 和岗位动态执行实时检索。将“证据回放”写清楚是为了区分演示数据与当日实时结果，并不影响 Skill 的实时运行能力。

## 隐私与边界

- 演示使用虚构简历，不公开真实候选人信息。
- 用户凭证不进入 Skill、仓库、报告或日志。
- 不绕过登录墙、验证码或平台访问限制。
- 无法完整读取的来源会被排除或明确降级。
- 不声称覆盖“全网所有面经”，只报告实际平台、查询、时间窗口和深读样本数。
